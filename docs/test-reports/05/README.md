\## Область, риски и исследовательские вопросы



Основное направление — разграничение доступа и полномочий при работе с одной заявкой.

Связанные вопросы: сохранность данных после отказа, согласованность API и UI,

корректность переходов состояния new → active → closed.

## Остаточные риски и следующие исследования

- Не исследовано: полномочия оператора по смене статуса в buggy-версии (не найден seed-оператор).
- Не исследовано: комментарии к заявке в состояниях new/active/closed и авторство комментария оператора.
- Не исследовано: каскадное удаление комментариев при удалении заявки.
- Следующий charter: проверить права оператора при работе с чужими заявками (чтение, смена статуса, комментарий) и корректность работы PATCH/DELETE на своей заявке в состояниях new/active/closed.
