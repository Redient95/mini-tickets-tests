\# BUG-05-01. Пользователь читает чужую заявку через API и получает 200 вместо 404



\## Состояние и классификация



\- Статус: Confirmed

\- Severity: S2 Major

\- Обоснование severity: нарушена изоляция данных между пользователями; обычный пользователь получает полное содержимое чужой заявки (id, author\_id, title, priority, status, created\_at). Формально это ближе к S1 Critical, но без изменения данных и без доступа к секретам оставлено S2 Major.

\- Priority: P1

\- Обоснование priority: уязвимость класса «утечка данных», воспроизводится 100 % и требует исправления до ближайшего выпуска.

\## Требование и риск



\- Требование: AUTH-03

\- Ожидаемое правило: «Пользователь видит только свои заявки. Просмотр чужой недоступной заявки возвращает 404».

\- Пользовательский риск: утечка содержимого чужих заявок между пользователями.

\- Технический риск: отсутствие проверки видимости при чтении заявки.



\## Предусловия



1\. Среда monolith/buggy запущена и готова (GET /health/ready → ready).

2\. Существует пользователь userA (`p05-buggy-a@example.test`) с активным токеном.

3\. Существует пользователь userB (`p05-buggy-b@example.test`) с активным токеном.

4\. Пользователь userA создал заявку, известен её id.

\## Итоговый ожидаемый результат



HTTP 404. Тело ответа: ошибка «не найдено». Чужая заявка не должна быть видна userB.



\## Итоговый фактический результат



HTTP 200. Тело содержит полное содержимое чужой заявки. userB видит данные, к которым не имеет прав.
